# LiveRecorder — 開発マスタープロンプト

あなたはシニアPythonエンジニアとして、Windows 11 / WSL2上で常時稼働する個人用ライブ配信自動録画・コメントアーカイブWebアプリケーション **LiveRecorder** を完成させてください。

TikTok LIVE・ツイキャスを監視して自動録画し、独立したコメント収集でSQLiteに保存する。動画とコメントSRT・音声SRT・統合ASSをWindows指定ドライブへ保存し、日本語の8画面で監視・検索・管理・設定・診断を行う。動画のWeb再生・ダウンロードは不要。実際に動作するソースコードと起動・導入手順を成果物とする。

### Phase 1：環境と最小計画

現在のブランチ・差分・実行環境・既存アプリ／DB／保存先／起動状態を読み取り確認し、専用隔離領域を確保する。Python 3.12/uv、FFmpeg/ffprobe、必要依存と採用版APIを確認する。最小起動・SQLite初期revision・設定・ログ・アダプターの構成を簡潔に決め、実装タスクを機能単位で記録。初回は `.python-version` の3.12と最小 `src/live_rec_lab/` パッケージ（CLI入口を含む）を作成し、uv_buildの最小起動を成立させる。初回は `uv sync` でロックを生成し、正式依存の確定後は `--locked` で再現する。依存はコア／Web→採用アダプター→speechの必要分だけ段階的に解決し、失敗時は未採用候補や解決不能なextraを一時分離して、最終的に正式pyproject.tomlとuv.lockへ収束。音声extra/GPUをコアの前提にしない。採用候補の互換性に応じ依存下限・グループを調整し、未採用依存を無条件に同期しない。必要なら実機許可を初回またはUI比較時に一括取得する。初期の広範な技術調査を終了させるためだけの作業は不要。

選択後の再開例：`B案を採用。記録済みの作業を再開し、prompts/implement.mdの完了条件まで継続してください。` 無回答を承認とみなさない。

作業メモはルートの `tasks.md` を使い、機能単位の実装・動作確認・利用保留／残件・再開点を簡潔に管理する。採用デザインは `ui/design.md`。採用技術・構成は実装後 `docs/architecture.md` 等にまとめればよい。既存の記録を二重作成・上書きしない。個々の検証観点を全件転記する必要はない。

`tasks.md` は機能ごとに「機能｜実装状態｜動作確認（実機／ローカル／未確認・結果）｜利用可否・残件／次の作業」を1行程度で記録し、重要な技術判断・外部保留の根拠と再開条件のみ短く追記する。検証観点・DDL列・API項目の全件転記や別追跡表は不要。実機確認の対象・版・環境は必要な範囲で記録し、状態と利用判定を混同しない。

## 中断・再開

UI選択・外部制限・使用量上限・強制中断時は、同じブランチ・作業ツリーと既存記録を再利用する。実装済みコード・最新の実機結果を確認して次の残件へ。実装可能な残件の列挙で完了としない。UI選択済みなら再比較不要。再開時は差分、作業メモ、稼働プロセスと実行版、直近の結果を確認し、次の未完了機能に進む。選択済みUI・完了済み調査・計画・試験を形式的に再生成せず、修正箇所と関連する最小回帰を実施する。
