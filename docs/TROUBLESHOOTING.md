# 切り分け

- ブラウザで開けない: `live-rec-lab url` がURLを出すか確認します。出ない場合はプロセスの生存状況を確認します。WindowsからWSLのlocalhostへ届かない場合は、WSLのネットワークモード（NAT／mirrored）を確認します。2026-11-23の試行では1構成でHTTP 200を確認しましたが、両モードの比較は未検証です。
- 配信者が未確認のまま: 通信失敗や資格情報不足です。オフラインとは別です。システム状態のイベントを見ます。
- ツイキャスが障害: `.env` の Client ID / Secret と、公式 API の 401 を確認します。
- 録画が始まらない: 保存先が空、ドライブ未マウント、空き容量不足、同時録画の上限のいずれかです。Linux 側へは切り替えません。
- SRTがない／失敗: まず「字幕対象なし（スキップ）」「コメント収集未実施・失敗」「コメント確定待ち」「同期不能・生成失敗」を区別します。時刻基準がないときは推測生成せず、動画とコメント原文を保持します。後着コメントがあれば収集終了・保存完了後の再同期状態を確認し、必要なら対象セグメントから再生成します（未実装の場合は実装状況を確認）。
- 二重起動: 2回目の `start` は拒否します。古いURLはPID等による生存確認を行います。複数試作で保存先が衝突するときは、DB・ログ・runtimeとWindows側動画・SRTの保存ルートをすべて確認します。**DBに保存された実効録画ルート**が環境変数と異なる場合にも注意してください。既存LiveRecorderとの同一／親子パス衝突が判明したら録画を開始せず、別の試作専用ルートへ設定変更して再確認します。
- 最新ジョブは完了だが録画が欠ける: 同一配信セッションの過去の全録画ジョブ、`invalid`／`pending`セグメント、欠損区間、実ファイルを照合します。最新ジョブの成功だけでセッション全体を完全取得とは判断しません。
- 録画ファイルが正常に見えない: 最終保存ファイルのサイズ・映像ストリームとコーデック・メディア長をffprobe等で検証します。0バイトMP4や映像不明のFLV、短いツイキャスHLSプリロールだけを成功扱いにしません。

- コメント期限削除の確認: 稼働DB／管理SRTから削除済みでも、**古い手動SQLiteバックアップに同じコメントが残る可能性**があります。バックアップは利用者が破棄・更新し、旧DBを手動復元するときは保持期限・SRT整合を再評価してください。
- ログの秘匿: 生の過去ログにキーやトークンを含む可能性があるときは閲覧APIで再マスキングします。ファイルを外部へ共有する場合は別途内容を確認してください。

## ログを確認する

「システム状態」で直近イベントと影響対象を確認します。確定仕様の「ログ」（`/logs`）では、記録された時刻・重要度・出力元を使って絞り込み、行の詳細を確認できます。ただし2026-11-23の試行記録では `/logs` は未実装です。

当該試行ではWSL2側の `~/.local/state/live-rec-lab/logs/app.jsonl` を参照します。`LIVE_REC_LAB_STATE_DIR` を変更している場合は、そのディレクトリの `logs/app.jsonl` を確認してください。発生時刻が古い場合は、同じ場所のローテーション済みログも確認します。実際の稼働インスタンス・記録時刻を照合し、古いエラーを現在の障害と断定しないでください。
