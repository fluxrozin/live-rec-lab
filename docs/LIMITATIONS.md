# 制限と検証範囲

## 実機で確認が必要な項目

- TikTokの実配信での開始／終了と録画・コメント収集、両サービスでの長時間・複数同時接続、配信全体の先頭／末尾と実際の同期精度。ツイキャス録画の確認範囲は下記を参照してください。
- Euler Streamの無料枠における、確認・署名・初回接続・再接続・長時間維持・複数同時接続の実測。ツイキャス公式APIのBasic認証での実残枠とエンドポイント間の共有単位。
- ツイキャスの匿名番号。視聴用WebSocketと公式コメントの一意照合が未検証のため、番号は取得できない状態で保持します。
- Windows側ドライブでの実ファイル確定、ローカルドライブの同一性とアクセス拒否、NAT／mirroredのWindows側localhost接続。
- Windows画面ロック・画面OFF、スリープ／休止、サインイン時のタスク実登録、Windows再起動を含む連続運用。

## 運用上の限界

- 録画は元の品質を維持して保存します。正常に再生できる媒体としての判定と、配信全体を欠損なく収録したことの判定は別です。配信中断や取得不能の区間は履歴の欠損で確認します。
- SRTは確認できたメディア基準、近似時刻、手動補正のいずれかで生成されます。外部プレイヤーで実際の同期を確認できます。
- 旧試作DBで、同じセッション内に重複セグメント番号がある場合は移行を保留します。旧試作のファイル所有情報が不足する場合は、既存ファイルの操作を保留します。
- Windows標準書体とNoto Sans JPの適用はクライアントにあるフォントに依存します。Noto Sans JPの読み込みを確認できない場合は代替フォントを使います。
- 自動期限削除の範囲は稼働DBとアプリ管理SRTです。ユーザー管理の旧手動バックアップは [導入手順](INSTALL_WSL2.md#バックアップと手動復元) に沿って取り扱ってください。

## ツイキャスのプリロール除外

- 2026-11-24の実配信1件で、本編78.976秒をセグメント1として確定し、映像と音声を最後までデコードできました。同じジョブの確定セグメントはこの1件で、録画欠損の記録は0件でした。配信元の映像と照合した先頭・末尾の完全性、他の配信パターンや長時間配信での再現性は未検証です。
- ローカルHLSと実FFmpegで、初期化切替、404後の起点再解決、同一ジョブ内の再接続を検証しました。保存済みの実録画を一時DBで再処理し、4.070秒のプリロールの破棄と本編の採番も確認しました。
- ファイル内容による照合は、正式保存前の小さな先頭候補のうち、既知の周期の繰り返しだけで構成されるものを対象にします。未知の素材や本編と混在した候補は、HLSに識別根拠がなければ残り得ます。除外は新しく確定する録画に適用されます。

今回のローカル検証、未検証、項目ごとの証跡は [要件追跡表](../specs/001-initial-live-recorder/traceability.md) を参照してください。
