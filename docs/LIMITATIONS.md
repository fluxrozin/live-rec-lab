# 制限と未検証

> **位置付け**：実装範囲・既知の制約・未検証事項の洗い出しと、受け入れ判定時に参照する運用補助資料です。 要件は `requirements.md`、画面仕様は `docs/UI_UX.md` を優先し、以下に含まれる過去の試作状況を新規実装の完成証拠としません。実装後は現行コード・テスト結果に合わせて更新してください。

**2026-11-23時点の実装試行についての記録**です。今回の文書更新では現行ソースコードや実行結果を再検証していません。ここに記載した実装状況を確定要件・現在の完成状態と混同しないでください。

## 当該試行で実装していないもの

- ブラウザ内の動画再生、ライブプレビュー、再生に合わせたコメント表示
- JSONL / CSV / TXT のコメント書き出し
- YouTube、ニコニコ、Twitch、SHOWROOM、文字起こし、通知、トレイ
- ツイキャスの新着ライブ用 WebSocket（`realtime.twitcasting.tv/lives`）をコメント取得に使うこと
- ツイキャス匿名番号の補助取得用WebSocket（要件では実配信での検証対象）。当該試行では番号は空のままです
- TikTokLive から動画 URL を作る第三の録画経路。録画は Streamlink、だめなら yt-dlp です
- アクセス制御、CAPTCHA、地域制限の回避

## 仕様変更への対応状況

- 録画動画・字幕はWindows側の保存先で利用し、Web UI/APIからダウンロードしない仕様です。当該試行の実装には旧ダウンロードリンクとAPIが残っていました。撤去・回帰確認は過去のタスク記録 `T036` の対象で、現行リポジトリで完了状況を再確認する必要があります。
- 当該試行のサイドバーは6項目で、`/streamers` は「監視対象」、`/recordings` は「配信記録」と表示され、独立した `/logs` は未実装でした。確定仕様は「運用・データ」4項目＋「管理」3項目の計7画面です。従来は `/system` の直近イベント要約とLinux側の `logs/app.jsonl` で切り分けていました。7画面・ログ閲覧は過去のタスク記録 `T037`〜`T040` の対象で、現行リポジトリと実ブラウザで要再確認です。

- 同一配信で最新ジョブだけが成功しても、過去の失敗・無効セグメント・欠損は残り得ます。画面・APIでは配信セッション全体の取得品質を全ジョブ・保持セグメント・欠損から集計する仕様で、当該試行での実装・受け入れ結果は未確認です。
- 録画ジョブ終了時のSRT生成と、コメント収集が続く場合の「コメント確定待ち」、後着コメント保存後の自動再同期・再同期失敗の区別は確定仕様です。当該試行での実装・検証は未確認です。
- 空試行の連番非消費と、複数録画ジョブを通じたセッション内連番の一意性、未確定レコードの復旧は、現行実装で改めて照合すべき事項です。
- 複数試作を同時運用する場合は、DB・ログ・実行状態に加え、Windows側の録画動画・SRT保存先も分離します。設定と現存ファイルでの確認が必要です。
- 現行要件では、コメント保存期限（初期無期限）によるSQLiteコメントと派生SRTの整合削除、論理削除済み配信者の再登録、同名ファイル衝突時のセッション固定識別子、SRT再生成の公開前後の版数競合対策、ログ読取バックエンドを初期機能に含めます。これらは本ZIPの仕様であり、当該試行の実装・動作を検証済みとするものではありません。

## ローカル試験で確認したもの

- 配信者の登録と重複拒否、未確認をオフラインにしないこと
- 短いオフラインで配信を終了しないこと、手動停止で自動録画しないこと
- 空ファイルを完成にしないこと、ローカルに生成した短い映像の確定
- コメント ID の重複排除、録画開始前の経過を空にすること、SRT の除外
- ツイキャス公式 API の模擬応答（404、401、コメント増分、残枠）
- 画面と API の CSRF、設定値の拒否
- 再起動時に未検証ファイルを完了にしないこと、SQLite の backup API
- WindowsからWSL2の`127.0.0.1`へのHTTP 200応答（2026-11-23、1構成のみ）。NAT／mirroredの双方での確認ではありません

## 未検証

- 実在の TikTok LIVE / ツイキャスへの接続、録画、コメント

- NATとmirroredの両構成を比較するWindows↔WSL2 localhost到達性試験。主要7画面と必要な下位ビューの実ブラウザ操作、画面幅1024／1280／1440pxの表示は未確認
- 画面ロック中の継続と、スリープ・休止での中断
- タスク スケジューラへの実登録
- SRTと映像PTSの実測同期。当該試行の字幕時刻は録画開始または最初のバイト時刻からの近似です
- 後着コメント保存後のSRT自動再同期、複数録画ジョブを含むセッション全体の取得品質判定、空試行と未確定セグメントを含む採番・復旧
