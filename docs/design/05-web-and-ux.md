# 05. Web/API・UI/UX基本設計

> 出典：[`requirements.md`](../../requirements.md) §2–3、§10.1.1.2、§11、[`docs/UI_UX.md`](../UI_UX.md) 全体。**UI詳細の正本は `docs/UI_UX.md`。**

## 1. Web構成

初期のWebフロントエンドは**FastAPI + Jinja2 + HTMX + 軽量JavaScript**。React/Next.js/Vueの独立SPAやNodeビルドを必須にしない。`src/live_rec_lab/web/` 以下にテンプレート・CSS・JSを集約する。

- `app.py`：FastAPI構築・lifespan・ルータ登録。
- `web/pages.py`：ページHTMLを返す。
- `web/partials.py`：必要時のみHTML断片を返す。
- `web/api.py`：将来クライアントとも共有する `/api/v1` のREST境界。
- `services/`：UI、CLI、RESTの共通の業務操作。UI側がDBを直接変更しない。
- HTMXの更新は入力中のフォーム、フォーカス、スクロール、検索条件を不必要に破壊しない。

## 2. 情報アーキテクチャ

サイドバーは**6つの主要ナビ**。セッション詳細・障害詳細・追加編集・設定内カテゴリは下位ビューとして扱う。「6つの画面しか作らない」という意味ではない。

| URL | ナビ表示名 | 主目的／重要な下位ビュー |
| --- | --- | --- |
| `/` | ダッシュボード | LIVE/REC/コメント収集の稼働状況、直近記録・異常への導線 |
| `/streamers` | 監視対象 | サービス別配信者、独立した監視/録画/コメント設定、追加・編集 |
| `/recordings` | 配信記録 | **配信セッション単位**の検索・詳細、セグメントとSRTの対応 |
| `/comments` | コメント | 配信横断検索、投稿者・日付などの絞り込み、関連セッションへ |
| `/system` | システム状態 | 保存先・外部ツール・直近異常・ログ・原因調査 |
| `/settings` | 設定 | 監視、録画・保存、コメント・SRT、表示、詳細設定 |

重要動線：ダッシュボードの稼働中セッション→セッション詳細→該当セグメント/SRT、監視対象→その配信者の配信記録、コメント→関連セッション。**コメントのみ保存されたセッションも配信記録に残す**。一覧→詳細→戻る際、検索条件・ページ位置を保持する。

## 3. 情報の粒度と状態表示

- **配信者**（監視の設定単位）、**配信セッション**（1回のLIVE）、**録画ジョブ**、**録画セグメント**、**コメント収集ジョブ**、**コメント**を視覚的に区別。
- 配信中＝緑、録画中＝赤、コメント収集中＝青。色だけで伝えず、状態文言・ピクトグラム等を併用。録画連動ロゴ／ファビコンと抑制可能な動きも現行UI仕様に含む。
- `UNKNOWN` ≠ `OFFLINE`、取得不能 ≠ `0件`、設定ON ≠ 録画中、処理受付 ≠ 完了、SRT未生成 ≠ 生成失敗、最新状態 ≠ 古いキャッシュ。
- 最終取得日時と表示更新の鮮度を共通位置に出す。自動更新を基本とし、**アプリ固有のページ再読込ボタンは設けない**（ブラウザ標準の再読込を利用）。機能固有の再試行・SRT再生成は別操作として維持。
- テーブル中心の一覧と、詳細への段階的展開を優先。巨大なカード群や説明文の追加だけで情報設計の不足を補わない。
- 数値単位、タイムゾーン、欠損表示、未保存変更、確定していない操作結果を一貫して扱う。

## 4. 現行デザインシステム（原本を尊重）

現在の `docs/UI_UX.md` は**単一の明るいライト系テーマ**で、フォントは「Windows標準（初期）」と「Noto Sans JP」の2種類。主要状態色はLIVE緑 `#168466`、REC赤 `#C93446`、コメント収集青 `#2876B9`。色は例示トークンであり実画面のコントラストを確認する。

ライト系1テーマを採用する。ダークテーマ、テーマ切替、OSの配色への追従、別フォントの追加は行わない。これらを変えるときは、先に `requirements.md` と `docs/UI_UX.md` を改訂する。Windows PCブラウザの1440px／1280px／1024px、拡大表示、キーボード操作、WCAG 2.2 AA目標を評価。

## 5. 安全な操作とAPI境界

- トグル・保存・録画停止/再開・ダウンロード・SRT再生成・削除は、処理中／受付済／成功／失敗／結果不明を区別し、二重操作を防ぐ。
- 破壊的操作は対象・影響範囲・復元可否を確認し、既定はキャンセル側に置く。
- ログインがなくても状態変更系リクエストにはCSRF・Origin/Host等の対策を適用し、GETで変更を実行しない。
- 動画のブラウザ再生・ライブプレビュー・コメント同期再生・HLS配信は初期のUIに入れない。動画とSRTは通常ダウンロードのみ。
- `/api/v1/*` は設計済みの**名前空間**であって、個々のRESTメソッド・payload・ステータスコードをまだ確定したことにはならない。実装featureの `contracts/` に検証付きで定義する。
