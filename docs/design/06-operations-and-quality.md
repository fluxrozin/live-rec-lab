# 06. 運用・セキュリティ・品質設計

> 出典：[`requirements.md`](../../requirements.md) §13–17、§20、§23、[`docs/UI_UX.md`](../UI_UX.md) §13–15。**設計ドラフト**。

## 1. 運用と起動

- WSL2 Ubuntu 24.04でPython 3.12 + uvにより直接実行する。Dockerは初期の必須条件としない。
- CLI候補は `start`、`status`、`url`、`backup`。起動後の動的ポートを標準出力と原子的な `endpoint.json` に記録する。
- Windowsサインイン後のWSL2/アプリ起動を運用対象に含む。Windowsロック中・画面OFFでは継続できるか実測。スリープ／休止／シャットダウン中は録画できない。
- 停止復帰時は、DBのジョブ状態、実在する録画子プロセス、Windows上の一時ファイル／正式ファイルを照合する。

## 2. 認証なしローカルアプリの防御境界

- デフォルトバインドは**`127.0.0.1`のみ**。LAN・インターネットへ認証なしで公開しない。
- 管理UI/APIは保存・削除を含む強い操作が可能。CSRF防止、Origin/Host検証、CORS最小化、GETによる状態変更禁止が必要。
- URL/パス正規化、SSRF、パストラバーサル、コマンドインジェクション、XSS、SQLインジェクションを防御。ダウンロードは録画保存ルート外のパスを返さない。
- TwitCasting Client Secret、Euler Streamキー等はGitや診断ログに入れない。`.env.example`はダミー値のみ。Linux通常ユーザー権限で動作。
- コメントには視聴者ID・本文が含まれる。個人用ローカル保管と削除・保存期間を運用設計に含める。

## 3. ログ・可観測性

構造化ログ（例：JSON Lines）に、UTC時刻、level、component、event_code、exception/traceback、correlation ID、セッション/ジョブ/配信者ID、プラットフォーム、外部HTTP status、レート情報、WebSocket切断理由、録画子プロセスexit code、再試行、欠損区間、容量異常を記録。APIキーや署名付きストリームURLはマスクする。

`system_events`はUI検索向けの**要約**。詳細ログとの対応をIDで追跡する。ローテーションし、外部障害を正常状態に握りつぶさない。動画、コメント、SRTの成否は個別にログ・画面表示する。

## 4. 復旧と障害分離

想定障害：WSL2停止、Python強制終了、SQLiteロック／書込失敗、外部ネット切断、API枠不足・認証失敗、子プロセス異常、コメントWS切断、容量不足、Windows録画先の書込拒否、未確定ファイル。

- 監視／録画／コメント収集の故障ドメインを分離。
- 二重録画・二重セッション・コメント重複保存を復旧時にも防ぐ。
- 復旧できなかった時間は `collection_gaps` に記録し、欠損を推測で補わない。
- データを失う可能性がある自動削除、破損ファイルの無検証上書き、別ドライブへの黙った代替保存はしない。

## 5. テスト構成

| 層 | 主な検証 |
| --- | --- |
| 単体 | ID正規化、入力検証、設定レート、ファイル名、ジョブ状態、時刻、重複排除、SRT生成 |
| 統合 | 配信検知→録画とコメントの独立開始、SQLite、動画確定、SRT、REST/UI、バックアップ |
| 障害 | 切断・再接続、子プロセス死活、DB書込、NTFS保存先、強制停止、未確定ファイル、二重実行 |
| 実機 | TikTok/ツイキャスAPI・権限、Windows↔WSL2 localhost、ロック・画面OFF・スリープの挙動 |
| UX | 主要6ナビと下位ビュー、実画面の情報階層、状態鮮度、キーボード、1024–1440px |

モックイベント、ローカルHLS、テストSQLiteでオフラインテストを成立させる。ただしモック成功を実サービス接続の動作確認と混同しない。

## 6. 受入・報告基準

各機能の結果を**実機検証済み／ローカル検証済み／未検証／実装不可**に分ける。少なくとも監視、録画、コメント収集、動画確定、SRT自動生成・再生成、コメント検索・ダウンロード、Windows側保存、再起動復旧、障害表示の結果を追跡する。実装・検証前の本設計文書は受入完了を主張しない。
