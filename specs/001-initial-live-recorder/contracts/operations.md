# 業務操作と状態遷移

| 入力・条件 | 結果 | 副作用 |
| --- | --- | --- |
| LIVE（同じ／新しいID） | LIVE。同じIDの既存セッションを優先。新しいIDは別セッション。 | 確認済みLIVEで有効な独立ジョブをそれぞれ最大1件起動。期限削除済みコメントの再収集は禁止。 |
| 明示OFFLINE／明示終了 | LIVE → ENDING | 既定15秒の猶予。監視で再確認する。録画は継続。 |
| ENDING中にLIVE | ENDING → LIVE | 同一セッションを継続。 |
| 猶予後の明示終了再確認 | ENDING → ENDED | 終了根拠と時刻を保存してジョブを安全停止。 |
| UNKNOWN／ERROR | 監視結果のみ更新。即座にENDEDへ遷移しない。 | 両ジョブが停止し正常確認不能なら既定120秒の孤立再確認後、終了未確認と理由を保存。後の同一IDを再利用。時間は設定して試験可能にする。 |
| 監視OFF | DISABLED。稼働セッションは安全停止後に終了未確認。 | 双方のジョブと新規監視を停止。OFFLINEは記録しない。 |
| 録画OFF | 対象の録画ジョブだけ停止。 | 他方は継続。有効ファイルは確定。 |
| コメントOFF（全体または配信者） | 対象の収集ジョブだけ停止。 | キューを排出し、全体OFF時も個別値を保持。 |
| ON復帰 | 監視ON、確認済みLIVE、対象機能ONで起動可能。 | 一意に新ジョブを起動。同一配信の手動録画停止が優先。 |
| 手動停止／再開 | 当該配信の録画自動起動を抑止／抑止を解除。 | 手動再開は有効設定かつ確認済みLIVEの同一セッションで新規セグメント。 |
| 録画子終了 | PENDING → STARTING → RECORDING → FINALIZING → COMPLETED／PARTIAL／FAILED／CANCELLED。再試行時はRECONNECTINGからSTARTINGへ。 | 内部取消・手動停止・設定停止・配信終了を区別。子を回収し、一時ファイルを検査。 |
| コメント接続 | PENDING → CONNECTING → COLLECTING。切断時はRECONNECTINGを経て再接続、終了時はCOMPLETED／PARTIAL／FAILED／DISABLED。 | 理由、受信・保存・失敗・欠損を記録。受信終了とDB書込完了を区別。 |

## 削除・SRT・保存の契約

- 削除要求は確定済みセッション、指定モードと明示確認を必須とし、進行中・未確定・復旧中なら競合を返す。操作が開始したら同じ操作を参照し、途中失敗の再試行は台帳と照合して処理する。DB更新前に対象ファイルの削除を確認する。
- コメント期限削除は独立ジョブで収束後だけ。排他フラグ／台帳を先に記録し、収集・SRT再生成を停止して管理SRTを先に除去する。DB側で確定するまで未完了とする。詳細は [DM-08・DM-09](../data-model.md)。
- SRT生成の入力は有効な動画、確定後の長さ、対象コメントと版数、同期根拠・補正。既定4秒、同時刻はDB ID順、負・末尾外・欠損区間は除外。投稿時刻が無い場合は受信時刻と根拠を記録する。公開前後の競合では未同期状態を返し、収集終了・キュー排出後に再試行する。既存字幕の所有確認に失敗した場合は元ファイルを保護する。
- 実効録画ルートはDB設定、環境値の順。比較対象は運用者が確認した実経路と実行中の別インスタンス。未確認・同一／親子・利用不可・容量不足時は録画起動を抑止し、現在の診断を返す。比較済みルートの変更時は再照合する。
- API時間計測は期限またはリトライ時刻まで非同期待機。ツイキャスAPIはコメント増分、録画復旧、定期監視、手動更新の優先度順に共有枠を調整する。認証・利用制限の回避は対象外。
