# 技術調査と採用方針

| 領域                 | 採用候補と判断                                                                                                                                                                                                                                                                                                                                                                                                               |
| -------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| TikTok検知・コメント | 公開room APIの状態を検証する。TikTokLive 7.0.1 の `is_live()` は終了以外の未知値も真にするため、その返値を監視状態として直接採用しない。コメントイベントはTikTokLiveを候補とする。署名は要件に従いEuler Streamの無料枠を調査し、匿名とキー付きの制限、必要な機能の利用可否を実測まで留保する。[TikTokLive](https://github.com/isaackogan/TikTokLive) · [Euler Stream 制限](https://www.eulerstream.com/docs/api/rate-limits) |
| 録画                 | 隔離fixtureでFFmpegを先行する。通常はStreamlinkを第一候補、yt-dlpを正当な取得経路に限定した代替候補とし、アクセス制限や明示拒否時は代替で回避しない。[Streamlink](https://github.com/streamlink/streamlink) · [yt-dlp](https://github.com/yt-dlp/yt-dlp)                                                                                                                                                                     |
| ツイキャス           | 公式APIのBasic認証、Get Current Live、Get Commentsを起点にする。公式HLSを優先し、コメント枠を確保する。匿名番号は確認・照合できる場合のみ保存する。[API v2](https://apiv2-doc.twitcasting.tv/)                                                                                                                                                                                                                               |
| SQLite・媒体         | SQLiteで独立結果を持ち、専用Linux領域の同一ファイルシステムで保存を検証する。Windows媒体の有効化には専用テスト領域で排他的確定の実証が必要。                                                                                                                                                                                                                                                                                 |
| 開発環境             | WSL2 Ubuntu 24.04.5、Python 3.12、uv 0.13.9、FFmpeg 6.1.1を確認。Windows通常録画先や実機動作は未検証。                                                                                                                                                                                                                                                                                                                       |
| ロック               | 既定sandboxのPyPI DNSと既存キャッシュの不足を確認後、パッケージ取得を許可された環境で解決。コアとspeech extraの両方を`uv.lock`に固定し、段階的に同期した。                                                                                                                                                                                                                                                                   |
| 音声                 | faster-whisper 1.2.1とCTranslate2 4.9.1を同期。モデル取得なしで架空のcueを出力した。ローカル初期化ではモデル本体・設定・tokenizerを要求し、不足時は保留する。                                                                                                                                                                                                                                                                |

配信・署名・認証APIへのリクエストは行っていない。

## 音声とコメント取得の追加確認

- 採用版 faster-whisper 1.2.1 の言語トークン100件に入力検証を合わせた。子では承認済みの置き場所を参照し、モデル未取得を保留にする。[faster-whisper](https://github.com/SYSTRAN/faster-whisper)
- ツイキャスのコメントAPIは指定limit未満のページも返し得る。短いページを終点にせず、件数、既知ID、ページ進捗を照合する。途中失敗や並び替わりでは受信済みのコメントだけ保存して前回のチェックポイントを維持する。[ツイキャス公式 Get Comments](https://apiv2-doc.twitcasting.tv/#get-comments)
