## User Scenarios & Testing

### User Story 1 — 見逃した配信を保存する (P1)

利用者は公開または許諾済みの配信者を登録し、配信後に動画、時刻付きコメント、コメントSRTを確認する。

**優先理由** 自動収集が手動記録の負担を減らす。  
**独立検証** 両サービスの模擬配信を1件ずつ終了まで通す。録画とコメントを片方ずつ失敗させる。

1. 【前提】登録・有効化済み配信者 【操作】配信を開始・終了 【結果】開始を検知し、セッションに動画とコメントを別の取得結果として保存する。
2. 【前提】録画またはコメントに障害 【操作】収集を継続 【結果】他方を可能な限り保持し、失敗・欠損・未確認を判別できる。
3. 【前提】確定動画の区間に保存済みコメントがある 【操作】録画完了 【結果】当該区間のコメントSRTが自動保存される。

### User Story 2 — 履歴・字幕を調べて管理する (P2)

利用者はPCの主要8画面で状況を確認し、履歴・コメント・発話を検索し、動画と3種字幕を外部プレイヤーで使う。

**優先理由** 取得したメディアを発見し、必要な字幕を使える。  
**独立検証** 部分取得・未確認を含む隔離fixtureを用意し、各画面と代表動線を開く。

1. 【前提】コメントのみのセッション 【操作】録画履歴で検索 【結果】セッションを発見し、コメントを閲覧できる。
2. 【前提】確定録画と利用可能な文字起こし環境 【操作】音声字幕を生成 【結果】音声SRTと、取得済みコメントに基づく統合ASSを管理できる。環境不足は理由付きで保留する。
3. 【前提】録画障害が発生 【操作】ダッシュボードから該当セッション、システム状態、またはログへ移動 【結果】影響と取得結果を確認できる。

### User Story 3 — 無人運用を安全に続ける (P3)

利用者は容量・監視・保存・診断の設定を管理し、障害や停止後に取得済みデータを保全しながら復帰する。

**優先理由** 既存の録画やコメントを守り、停止理由を調べられる。  
**独立検証** 専用データと媒体で停止・再開、容量不足、競合、期限削除とバックアップを検証する。

1. 【前提】Windows録画先に書けない 【操作】監視を続ける 【結果】録画・媒体操作だけ保留し、安全なコメント収集と管理画面を継続する。
2. 【前提】コメントの保持期限が経過 【操作】期限処理 【結果】対応するコメントSRTとASSを先行して削除し、動画・音声SRTを保持する。復元後も期限削除済みASSは復活しない。
3. 【前提】取得中に停止 【操作】次回起動 【結果】中断を明示し、安全に確認できた記録を継続する。未確定媒体は照合対象になる。

### Edge Cases

- 状態取得失敗・未観測・未収集、コメント未観測と取得済み0件、欠損と成功を区別する。
- 同名の管理外ファイル、ファイル差し替え、同名化する別配信者ID、サービス横断の同一IDを扱う。
- 起動ポート競合・保護領域不明・DB復元途中・外部制限時は対象操作を安全に保留する。

## Requirements

### Functional Requirements

- **FR-001** 両サービスで対象の登録・変更・有効化・無効化・論理削除、監視・検知を提供する。TikTokは最大10回／分、ツイキャスは最大60回／分（初期10回／分）。
- **FR-002** 配信・録画・コメントを別状態とし、配信者・セッション・セグメントを関連付ける。録画とコメントの片方の障害から他方を保護する。
- **FR-003** 通常は指定Windowsドライブ、隔離は専用Linux領域を使う。固定命名、非上書き、同一IDのフォルダ共有、異IDの衝突分離、所有・世代照合を守る。
- **FR-004** セッションにコメントの時刻・投稿者・欠損を保存して検索できる。録画完了時には対象区間ごとのコメントSRTの生成または対象なしを記録する。
- **FR-005** 音声SRT・統合ASSの生成と再生成、発話検索、理由付き保留を提供し、公開失敗時は既存版を保全する。
- **FR-006** 確定8画面と各詳細への動線を提供する。初期UIは3案から利用者の明示選択を受け、ライトとフォント2択を維持する。媒体のHTTP配信・ブラウザ再生は提供しない。
- **FR-007** ローカルHTTP防御、秘密・入力・ログの保護を維持する。実運用と隔離のデータ・ポート・動作を分離する。
- **FR-008** 構造化ログ、診断、容量、監視設定、プロセス排他・停止・復帰、Windows起動時の自動運用を提供する。
- **FR-009** 所有・世代照合後の削除、保持期限、整合バックアップとマーカー付き復元を提供し、期限削除済みの成果物を復活させない。
- **FR-010** 公開／許諾済み配信に限定し、制限時に回避しない。配信元との実通信はモード別許可・共通排他・永続予算を守る。開発・試験は既定で外部通信を拒否する。

### Key Entities

- Streamer、StreamSession、RecordingSegment は登録対象・配信・確定媒体を表す。
- Comment、SpeechCue、SubtitlePublication は取得内容・時刻・セグメントとの対応・公開版を表す。
- RuntimeConfig、SystemEvent、DeletionOperation、RequestBudget は設定・診断・保全処理・外部枠を表す。

## Success Criteria

### Measurable Outcomes

- **SC-001** 両サービスで1件ずつの代表通し試験が完了し、録画とコメントの各単独障害でも他方に取得結果が残る。
- **SC-002** 足りない区間を除外し、3種の字幕それぞれが対応する録画と関連付く。既存媒体を置いた非上書き試験で変更は0件。
- **SC-003** 8画面を開き、録画・コメント・発話検索と障害情報へ到達できる。初期画面案の選択記録は1件。
- **SC-004** 代表競合・期限処理・復元中断の試験で、他の運用領域への変更、秘密・媒体公開、期限削除済みASSの復活、無許可外部接続はいずれも0件。

## Assumptions

- 単一利用者のPCローカル運用。試験は架空の対象と隔離媒体で開始する。
- 実配信・Windows保存先・音声実機の利用可否は、別途実測後に機能単位で判定する。
- UI案の利用者選択は法則が確定済みの設計工程であり、仕様の保留点はこの選択結果に限る。
