## User Scenarios & Testing

### US1 配信を検知し、録画とコメントを個別に記録する（P1）

利用者は公開または許諾済みのTikTok LIVE／ツイキャス配信者を複数登録する。各サービス内の共有監視枠で配信を検知し、録画とコメント収集を個別に設定・運用する。ローカルHLSと模擬配信／コメントを用いて、配信開始からセッション・ジョブ・保持動画・コメント・SRTの相互参照までCLIで独立検証できる。

1. 配信IDを伴うLIVEを検知すると、同一セッションで許可されたジョブを最大1件ずつ起動する。
2. 一方の障害、設定OFF、通信断はもう一方の動作から分けて記録する。手動停止は同じ配信の自動録画に優先する。
3. 状態不明中は稼働ジョブを維持する。明示終了の猶予中にLIVEへ戻れば同じ配信を続ける。両ジョブが止まったままなら再確認期限の後に終了未確認を記録する。

### US2 取得した記録を探し、保存・削除の結果を確認する（P1）

利用者は配信セッション単位で動画・コメント・欠損を探す。有効な動画とDBの原文から暫定／確定のSRTを生成し、必要に応じ再生成する。時刻と故障を制御できるローカルデータで独立検証できる。

1. 複数ジョブでも保持セグメントの連番を継続し、過去の欠損や無効ファイルを新しい成功で隠さない。
2. 部分取得でも動画とコメントを保全する。0件の字幕対象、収集未実施、同期待ち、同期不能を区別する。
3. 安全に停止・確定した配信だけ削除できる。ファイルだけを削除するか、続けて履歴も消すかを確認する。コメントの期限削除と再登録時の履歴保全を独立して確認できる。

### US3 運用画面で設定、記録、障害を調べる（P2）

利用者はローカルのブラウザから指定順の7画面を使う。記録の有無と取得状態をそれぞれ確認し、関連記録と診断・ログの間を移動する。記録済みのデータとブラウザを使い、URL、画面操作、幅、状態表示、ログ再マスキングを独立検証できる。

1. 監視や表示・保持条件の変更は保存結果を確認でき、必要な設定の反映時期を示す。
2. システム状態から記録のある相関条件でログを開き、検索位置を保って関連セッションを往復できる。
3. 未取得、エラー、古い情報、正常な空、検索結果0件、期限削除を区別し、表示時刻と操作結果を確認できる。

### US4 WSL2 上で起動し、停止や障害から復旧する（P2）

利用者は一般ユーザーで起動し、動的ポート・生存確認付きURL、手動バックアップ、状態確認と安全停止を使う。分離した検証用環境で再起動と競合を再現し、Windows固有の動作は実機で確認する。

1. 起動前に既存アプリとは異なる実効録画ルートを確認する。マウント・権限・容量・重複に問題があれば録画を抑止する。
2. 確定・削除・SRT公開の途中停止から復旧する。管理対象の取得済みデータと既存アプリのデータを守る。
3. バックアップ作成時に保持期限の範囲を説明し、手動復元後は再評価してから通常運用へ復帰する。

### Edge Cases

- HTTP拒否、制限、空本文、不明な配信状態、終了猶予中の復帰、配信IDなし。
- 外部アダプターの一方だけ利用不可、コメント元IDなし、匿名番号が曖昧。
- Windowsの同名、親子ルート、予約名、ケース／Unicode差、管理外ファイル、マウント消失。
- 空試行、無映像、リマックス失敗、確定直前／直後の強制終了、後着コメント、古いバックアップ。
- 未確定のセッションへの削除要求、部分削除の再試行、期限削除中のコメント保存／SRT生成、旧ログの秘密情報。

## Requirements

### Functional Requirements

| ID | 要件 | 正本 |
| --- | --- | --- |
| FR-001 | TikTokユーザーID／プロフィールURL・ツイキャスIDを検証し、サービス・正規化IDで配信者を一意に管理する。履歴あり削除は論理削除、再登録時は3設定すべてを再指定し既存行を復帰する。 | §4.1.1、§5.1、§9 |
| FR-002 | 監視枠はTikTok最大10回／分、ツイキャス初期10・最大60回／分。小数設定、サービス内公平巡回、次回から反映、コメント優先の実効枠、バックオフと診断を備える。 | §4、§5.2 |
| FR-003 | 配信IDで重複抑止し、明示OFFLINEから終了猶予を開始する。終了未確認の有限収束と再検知時の同一セッション復帰を備える。 | §5.3–5.4 |
| FR-004 | 録画・コメントを独立起動、停止、再試行する。監視OFFは双方を停止、各OFFは該当ジョブを停止、全体コメント設定と個別設定はAND。手動停止を同一配信で優先する。 | §6.1、§7.1 |
| FR-005 | 優先エンジンと品質設定、並行録画、無劣化確定・再接続を用意し、取得済みメディアと欠損を維持する。確定後に映像・音声・サイズ・長さを照合する。 | §4.1.4、§4.2.3、§6、§8 |
| FR-006 | コメント原文と実際に取得した投稿者・各時刻を永続化する。重複排除、キューの上限と排出・再試行、オフセット、欠損、取得件数と状態を管理する。 | §4.1.3、§4.2.2、§7.1–7.5、§8 |
| FR-007 | 対応動画ごとにSRTを自動生成／再生成し、0件スキップ・暫定・同期法・版数差・後着・生成失敗・期限削除を区別する。最後の正常版と原文を保全する。 | §7.7–7.8 |
| FR-008 | 配信者／日付別のWindows保存、サービスを含むファイル名、フォルダ安全名の永続対応、セッション横断採番・衝突識別子・排他的発行と起動時復旧を備える。 | §6.5、§9.4、§10.2–10.3 |
| FR-009 | DB優先の実効ルートと別インスタンスのルートを照合し、同一・親子・未確認時は録画を保留する。ドライブと容量を診断し、未確定データを保全する。 | §2、§10.1、§10.4–10.5 |
| FR-010 | ファイルのみ／ファイル＋履歴を台帳に記録して処理する。容量・動画期限の自動削除は初期OFFでファイルのみ。コメント期限は独立した初期0日でSRT先行・DB後続とする。 | §9.11、§10.4、§13.6 |
| FR-011 | 指定順の7画面で配信・ジョブ・SRT・表示データ・操作結果を区別し、表示時点、検索とページ位置、セッション・診断・ログの相互導線を提供する。 | §11、UI §3–16 |
| FR-012 | 日本語・単一ライトテーマ・指定2フォント、状態と安全操作の表示、PC幅・キーボードでの操作性を実現する。 | §11、UI §2、§5–6、§13–16 |
| FR-013 | 履歴は全ジョブ・動画・欠損をまとめ、コメントのみの配信を含む。時系列のコメント横断検索、詳細、期限削除済み表示を用意する。 | §7.6、§8、§11.4–11.5 |
| FR-014 | 許可済みの現行／ローテーション済み内部ログとイベントをサーバー側で段階的に読取・検索する。秘密情報を記録前と応答前に除去し、非秘匿の詳細・コピーを提供する。 | §11.6–11.7、§14.3 |
| FR-015 | 単一プロセスでループバックにバインドし、起動URLを生存確認付きで提示する。変更をHost・Origin・CSRFで保護し、動画やSRTのWeb配信機能を備えない。 | §2、§12、§13 |
| FR-016 | WSL2で起動・停止・復旧、Windowsサインイン後の起動、ローテーションと一貫した手動バックアップを用意する。復元時はコメント期限・SRTを再照合する。 | §14–16 |
| FR-017 | Feature選択を固定し、原本の全節・固定TC／AC・UI受入項目からテスト証跡まで追跡する。実配信／Windows／ローカルの検証状況を区別する。 | §17、§19–24、開発憲法 |
| FR-018 | 利用条件と録画権限を確認し、公開または許諾済み配信を扱う。匿名番号は視聴用経路とAPIの一意照合が実証された場合だけ採用する。 | §1.2、§4、§13 |

### Key Entities

- 配信者・配信者フォルダ対応・配信セッション。サービス別のID、観測時刻、固定した保存先と終了根拠を保持する。
- 録画ジョブ・録画セグメント・コメント収集ジョブ・コメント・欠損区間。実行レベルの結果とセッション全体の集計を分ける。
- システム設定・実行インスタンス・診断イベント・削除操作。操作の受付、実行、復旧、確定の根拠を保持する。

## Success Criteria

- SC-001 2サービスの公開／許諾済み配信について、検知・録画・コメントを独立に試験し、保存物と時刻を同一配信IDで照合する（AC-001〜021）。
- SC-002 指定URL・順序の7画面を幅1024／1280／1440pxで表示・操作し、検索、設定、欠損、ログ秘匿を確認する（AC-022〜037）。
- SC-003 Linux側での起動・再起動・停止に加え、Windowsロック・サインイン後起動、正しい保存ルートとバックアップの境界を確認する（AC-038〜045、050〜053）。
- SC-004 初期対象外のWeb視聴機能が存在せず、固定AC 55件とTC 69件の対応と検証結果を確認できる（AC-046〜049、054〜055）。

## Assumptions

- Windows PCの単独利用を対象とする。録画には事前に確認した専用Windowsドライブが必要。
- 例外時は取得・確認できた事実を残す。外部サービスの契約と環境の制約は [実現性調査](research.md) に記録する。
- 通知配送、メディア再生／公開、字幕以外の書き出し、文字起こし、追加サービスは原本の初期範囲外とする。
