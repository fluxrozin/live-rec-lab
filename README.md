# LiveRecorder

LiveRecorder は、Windows 11 上の WSL2 で動かす個人用のライブ配信記録アプリです。TikTok LIVE とツイキャスを監視し、配信が始まったら動画を自動で録画し、視聴者コメントを時刻と投稿者情報つきで残します。操作は Windows の PC ブラウザから行います。

録画ファイルは Windows 側の指定ドライブに保存します。エクスプローラーから開くか、管理画面からダウンロードして外部のプレイヤーで見ます。コメントは画面で検索でき、録画が終わったセグメントごとに SRT を自動で作ります。

このリポジトリにあるのは要件（`requirements.md`）と画面設計（`docs/UI_UX.md`）です。以下は、そこで確定している使い方です。起動用のコマンドは、本体ができてから使います。

## 起動して画面を開く

LiveRecorder は WSL2（Ubuntu 24.04 LTS を基本）の中で、Python 3.12 のプロセスとして動きます。

1. WSL2 で LiveRecorder を起動する。CLI には `start`、`status`、`url`、`backup` を用意する。
2. コンソールに出る URL を、Windows のブラウザで開く。同じ URL は `~/.local/state/live-recorder/runtime/endpoint.json` にも残る。`url` でも確認できる。
3. ポートは空いている番号を自動で割り当てる。固定ポートは設定で選べる。
4. ログインなしで開く。初期状態の待ち受けは `127.0.0.1` だけで、自分の PC から使う。

管理画面からは録画の削除や設定変更ができる。LAN やインターネットには出さない。

Windows の画面ロック中とディスプレイ OFF 中は録画を続ける。スリープと休止では処理が止まる。Windows へサインインしたあとの自動起動と、再起動後の監視再開を前提にする。

## 配信者を登録する

サイドバーの **監視対象**（`/streamers`）で配信者を追加する。

- TikTok はユーザー ID、`@username`、プロフィール URL のいずれでも登録できる。
- ツイキャスはユーザー ID で登録する。API は Client ID と Client Secret による HTTP Basic 認証を使い、利用者ごとのログインは不要。
- 同じアカウントは重複して登録できない。
- 配信者ごとに、監視、録画、コメント収集を別々に有効にできる。

対象は、公開配信か、録画してよい権限がある配信に限る。

## 配信が始まったあと

監視はサービスごとの回数で行う。初期値はどちらも 10 回／分。上限は TikTok が 10 回／分、ツイキャスが 60 回／分。回数は配信者ごとではなく、そのサービス全体で共有する。設定画面で変更でき、次回の巡回から反映される。ツイキャスでは、公式 API の枠をコメント収集に優先して使う。

配信開始を検知すると、録画とコメント収集をそれぞれ起動する。一方が失敗しても、もう一方は止めない。

- 配信中、録画中、コメント収集中は別の状態として表示する。取得できない状態を「オフライン」や「0 件」にはしない。
- 録画は Windows 側の保存先へ直接書く。既定の例は `D:\LiveRecorder\recordings`（WSL2 からは `/mnt/d/LiveRecorder/recordings`）。ドライブは設定で変えられる。
- フォルダは配信者 ID、その下は日付。ファイル名で TikTok とツイキャスを区別する。
- コメントの正本は SQLite に残る。録画セグメントが確定すると、同じフォルダに同名の SRT を 1 つ作る。コメントの書き出し形式は SRT だけ。

## 記録を探す

サイドバーは次の 6 項目。詳細や編集は、各画面の中で開く。

| 表示名         | URL           | 主な操作                                                                 |
| -------------- | ------------- | ------------------------------------------------------------------------ |
| ダッシュボード | `/`           | いま配信中・録画中・収集中の数、本日の件数、空き容量、直近の記録と障害   |
| 監視対象       | `/streamers`  | 配信者の追加・編集・削除、監視と録画とコメント収集の ON/OFF              |
| 配信記録       | `/recordings` | 配信セッションの検索、動画のダウンロード、セグメントごとの SRT、履歴削除 |
| コメント       | `/comments`   | 本文・投稿者・配信者・日付での検索と閲覧                                 |
| システム状態   | `/system`     | プロセス、保存先、依存ツール、直近のエラー                               |
| 設定           | `/settings`   | 監視頻度、保存先、同時録画数、タイムゾーン、フォント                     |

配信記録の単位は、1 回の配信セッションである。動画がなくてもコメントが残っていれば、そこからコメントを開ける。一覧から詳細へ進んで戻っても、検索条件は維持する。

動画はダウンロードして外部のプレイヤーで見る。ライブのプレビューや、再生に合わせたコメント表示は管理画面に置かない。

## 設定で変えること

**設定**（`/settings`）で、次を変更する。

- サービスごとの監視頻度
- 同時に録画する上限、録画品質、保存先、空き容量の下限、保存期限
- タイムゾーン（初期値は `Asia/Tokyo`）
- 画面のフォント（Windows 標準、または Noto Sans JP）
- Web のポート（自動割り当て、または固定）

データベース、ログ、起動 URL は WSL2 の Linux 側に置く。録画動画と SRT だけを Windows のドライブに置く。

| 置き場所                               | 内容                         |
| -------------------------------------- | ---------------------------- |
| `~/.local/share/live-recorder/data`    | SQLite                       |
| `~/.local/state/live-recorder/runtime` | 起動 URL とプロセスの状態    |
| `~/.local/state/live-recorder/logs`    | ログ                         |
| `/mnt/d/LiveRecorder/recordings`（例） | 動画セグメントと対応する SRT |

SQLite の手動バックアップは `backup` で行う。動いているデータベースファイルを、そのままコピーしない。
